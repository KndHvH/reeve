# Technical decisions

A short record of each choice and its rationale, so that it can be questioned and revised.

| Date | Decision | Reason |
|------|----------|--------|
| 2026-10-28 | Python 3.13 + tkinter drawn on a Canvas (no native widgets) | Lowest possible RAM (~30 MB). The Canvas allows a modern look without Qt/Electron. |
| 2026-10-28 | Digit template matching instead of OCR | The game font is fixed. ~1 ms per read vs. tens of ms (Tesseract) or hundreds of MB (EasyOCR). |
| 2026-10-28 | Capture only ROIs with `mss`, 1 read/s (configurable, 1–2 s) | User requirement: nothing needs to be instantaneous. Capturing the whole screen wastes CPU. |
| 2026-10-28 | Resolution via `GetClientRect` (ctypes) and UI scale via multi-scale anchors | No fixed per-resolution profiles. Detection runs once and is redone if confidence drops. |
| 2026-10-28 | DPI-aware process (`SetProcessDpiAwareness(2)`) | Otherwise, with Windows scaling ≠ 100%, coordinates are virtualized and the ROIs are misplaced. |
| 2026-10-28 | "Idle TC" by heuristic: total villager count not increasing for > ~22 s | Without the TC selected, the queue is not visible. A villager takes 20 s. |
| 2026-10-28 | Anchor = the panel's icon column (house/food/wood/gold/stone), cropped from `tests/fixtures/720p_0036.png` | Tall and uniquely shaped, so it pins the scale well. Score 0.996 on real captures. |
| 2026-10-28 | Two-step detection: coarse scan at 360p + refinement at the original resolution | The first version took 0.6 s (720p) to 5.8 s (4K). Now 37 ms (720p) to 133 ms (4K), and it runs only once. |
| 2026-10-28 | Reference = 720p (the user's resolution), not 1080p | Templates come from real captures. On larger screens the anchor is upscaled, and NCC tolerates this well. |
| 2026-10-28 | Clock: region relative to the top center, scaled by the same scale as the panel | **Not yet validated** with another UI scale. The clock background is semi-transparent and path markers (yellow dots) can fall inside the region: the reader will filter by color/shape and check that time only moves forward. |
| 2026-10-28 | "Idle TC": use the production queue above the panel (villager icon + progress bar) as the primary signal; the 22 s heuristic is kept as a fallback | User suggestion: the queue is shown without selecting the TC. |
| 2026-10-28 | Capture only while AoE4 is in the foreground (`GetForegroundWindow`) | `mss` copies the screen, not the window: with the browser on top, a YouTube screenshot was captured. The anchor already rejected it (score 0.42), but capturing makes no sense. |
| 2026-10-28 | Do not assume the UI scale follows the window height | At 1280x720 and 1280x768 the UI has exactly the same size in pixels. The anchor measures the real scale, so the code uses the height only as an initial guess. |
| 2026-10-28 | Glyphs normalized to 16×24 with a 1 px context margin, no blur | Compared by leave-one-out on the 8 fixtures: 144/144 glyphs correct (8×12 without a margin failed and scored 0.55 on correct digits due to subpixel effects). |
| 2026-10-28 | Touching digits ("40", "/40" at 720p) are split at the weakest column when the blob exceeds 7.5 px × scale | Column projection alone merged these glyphs. |
| 2026-10-28 | Glyph bank = real labeled samples (`assets/glyphs/<char>/*.png`), not a rendered font | The folder can be opened to see the reference. It grows with every capture labeled in `aoe4ov label`. |
| 2026-10-28 | Clock: vertical sliding window, choosing the valid position with the **highest confidence** (digits of equal height) | The clock moves down on age-up (reported by the user). The first valid position cut 1 px from the top ('2' became '7'); sorting by height picked up building texture ("5045"). |
| 2026-10-28 | Production queue: NCC of the villager icon above the panel, threshold 0.6 | In the captures: idle ≤ 0.43, producing ≥ 0.70 (the worst case has the count "3" drawn on top). The villager technology icon (brown background) scores ~0.40. |
| 2026-10-28 | Live mode captures only 2 rectangles (bottom-left corner + clock), ~5% of the screen | A test ensures the reading is identical to the full-screen one. |
| 2026-10-28 | Current cost per read: ~11 ms (≈7 ms is the production queue); clock without a reliable cache ~50 ms | Acceptable at 1 read/s (~1% of one core). Optimization pending for `perf-guardian`: a smaller queue region or checking every 2–3 s. |
| 2026-10-28 | The clock uses a **local contrast** mask (pixel − neighborhood mean > 60); the panel keeps absolute brightness | On age-up the clock moved down over beach sand; the light sand, seen through the translucent background, entered the mask and the reading became a false "4:08:53". On the panel the background is always dark and the dimmed zeros need the absolute threshold. |
| 2026-10-28 | Clock: at each window position, keep only glyphs with the same top/height as the majority | Box edges against a bright building became strokes read as "1" (score 0.7–0.8). |
| 2026-10-28 | Clock region increased to 84 px in height (ref.) | On age-up the clock moves down ~31 px; headroom for larger scales. |
| 2026-10-28 | Default `watch` read rate: **once every 2 s** | User request after the first live match. |
| 2026-10-28 | Trimming weak glyphs at the edges only for the clock; on the panel, a weak glyph invalidates the reading | In the live match the "0" of "7/10" was cut off and read as "7/1", a wrong value that looked valid. |
| 2026-10-28 | `pop` uses a color mask: max(R,G,B) channel, without requiring neutral text | Population turns yellow near the cap and red at the cap (confirmed by the user); it stayed "?" for 20 s live. |
| 2026-10-28 | Each cycle, a cheap anchor check at the known position; hidden panel = menu/pause (reading skipped, `panel_hidden`/`panel_visible` events logged); hidden > 30 s = end of match | The user opened the menu mid-match and `watch` recorded garbage readings. Against the AI the menu pauses the clock; in multiplayer it does not, and the timeline just has a gap. |
| 2026-10-28 | The `watch` log separates capture time (`grab_ms`) from read time | Live at 1080p it measured 25–50 ms, but the reader alone takes ~10 ms at that scale: it remains to be seen whether the extra time is the capture (mss) or the clock cache missing. |
| 2026-10-28 | Menu also detected by **brightness**: anchor below 70% of normal in-game brightness, or shape below 85% of calibration | Session 20261028-163342: when the menu opens the screen darkens uniformly and the shape (NCC) stays high; the reading came out "pop 0/0". Brightness dropped from ~45 to 9; at the start of the fade the shape dropped from 0.91 to 0.75. |
| 2026-10-28 | Clock cache: previous position ±1 px, accepted if the digit height has not decreased | At 1920×1351 (UI 1.509×) clock confidence sits around 0.70 and never exceeded the required 0.85; every read redid the scan (~25 ms). Now ~13 ms for the whole read. |
| 2026-10-28 | The production queue accepts multiple templates, each with the scale at which it was cropped | At 1.509× the upscaled 720p icon scores 0.64 while producing (threshold 0.6): a thin margin. A clean crop at that scale is still missing. |
| 2026-10-28 | Overlay in tkinter with `WDA_EXCLUDEFROMCAPTURE` + click-through + no focus; nothing drawn inside the read regions | The overlay sits on top of the game and capture copies the screen: without the exclusion it would appear in its own readings. Tested: with the exclusion the capture does not show the overlay; without it, it does. |
| 2026-10-28 | Live reading engine (`live.py`) shared by `watch` and `overlay` | Calibration, menu/pause handling and logging in one place. |
| 2026-10-28 | Process RAM/CPU via Win32 (`GetProcessMemoryInfo`, `GetProcessTimes`), no psutil | No new dependency. Measured on the simulated overlay: ~63 MB, CPU ~0.2%. Above the 50 MB target: numpy + Pillow + Tk. Review with `perf-guardian`. |
| 2026-10-28 | Anchor without the house icon: template = food/wood/gold/stone, with `template_offset` to keep the origin | At the population cap the house turns red with a "!": the score dropped from 0.90 to 0.757 and the menu check (85% of calibration) would stop reading exactly when the player is housed. Bonus: the scale became more precise (1.486 vs. 1.509 before; measured in pixels: 116/78 = 1.487). |
| 2026-10-28 | Second villager icon template, cropped at 1920×1351 (summary icon, no bar); threshold 0.63 | 14 images at 3 resolutions: idle ≤ 0.49, producing ≥ 0.78. |
| 2026-10-28 | Window re-read every cycle (0.08 ms); size changed → recalibrate; position changed → just continue (regions are relative to the game area) | User request: change resolution/position while in use. |
| 2026-10-28 | Panel missing → new anchor search every 3 cycles; if found at another position/scale, continue in the same session (`recalibrated` event) | Changing the UI scale in the options does not change the window size; previously this was treated as "menu" for 30 s and ended the log. Cost ~80 ms every 6 s, only while the panel is missing. |
| 2026-10-28 | Production queue: region downscaled to the reference scale before searching, all templates at that scale | User's idea. At 1920×1351: 15.7 → ~8 ms. Separation over 20 images (720p, 768p, 1351p, 720p→1080p): idle ≤ 0.51, producing ≥ 0.78. |
| 2026-10-28 | Digits are **not** downscaled to 720p | They are already normalized to 16×24 (size does not matter). The lower confidence at 1080p (~0.8 vs. ~0.99) comes from the game re-rendering the font at each resolution (stroke weight, anti-aliasing, pixel snapping), not from size: downscaling does not make the 1080p "5" match the 720p one. Samples from other resolutions increase the margin, but a set per resolution is not required. |
| 2026-10-28 | Menu/pause detected by the anchor's **contrast** relative to the template's (`contrast` < 0.7, alongside `shape`), no longer by brightness relative to calibration | Sessions 170009/170116: calibrating while the screen was still dark let the menu pass as "visible"; the bluish veil when returning from the menu **increases** mean brightness. Contrast: in-game 0.88–0.89 (14 fixtures, 3 resolutions); menu/veil 0.03–0.38 (fixtures `neg_menu_dark.png`, `neg_menu_veil.png`). |
| 2026-10-28 | A missing anchor (e.g. options screen) while a match is open only ends the session after 30 s | The user changed the resolution in the options and the match was split into two sessions. |
| 2026-10-28 | A queue score between 0.55 and 0.72 saves `doubt_queue_*.png` | Live scores of 0.58–0.63 appeared, right at the threshold: they need to be inspected. |
| 2026-10-28 | "pop 10/1" with a tooltip covering the number is deferred to the state layer (M5): a new value only counts after 2 identical readings | The panel really was visible (contrast 0.90); no panel check catches this (fixture `tooltip_over_pop.png`). |
| 2026-10-28 | Project language switched to English (code, docs, UI text, data names, commits); earlier git history stays in Portuguese | Professional, consistent codebase; history not rewritten to avoid force-pushing. |
| 2026-10-28 | State layer: slow fields (population, idle, villagers per resource, villager production) need two identical consecutive reads; resources are taken as read; the clock only moves forward by about the elapsed wall time, larger jumps need a confirming read | A tooltip produced "10/1" for one frame and one clock read came out as 12:31 at 1:23. Resources change on almost every read, so confirmation would never settle; rules add persistence instead. The clock may legitimately jump after a menu in multiplayer (35:48 → 36:24 observed). |
| 2026-10-28 | Rules in `config/rules.json`: idle ≥ 1 for 4 s; town center idle for 6 s and suppressed while housed; housed at cap − 1 (ignored at 200); floating > 400 before 5:00, > 800 before 15:00, > 1500 after | Defaults agreed with the user; the reason values are logged with every alert (`alert_on`/`alert_off` events). |
| 2026-10-28 | Clean overlay (alert cards only, redrawn only when alerts change) is the default; the previous view moved to `overlay --debug` | User request: the debug view is for validation, the clean one for playing. |
| 2026-10-28 | `aoe4ov replay` runs state and rules over a recorded log | Rules can be tuned against real sessions without playing. |
| 2026-10-28 | Three severities: info (blue, silent), warn (yellow), critical (red). Idle villagers 1–2 warn / 3+ critical; town center idle warn after 6 s, critical after 10 s; population ≥ 80% of the cap warn, ≥ 90% critical; floating resources escalate when the stockpile already exceeds a later phase's limit (e.g. > 800 before 5:00 = warn) | Defined by the user after the first live test of the alerts. |
| 2026-10-28 | Sound for warn/critical via `winsound` (stdlib, async): on appearance, on escalation and every 5 s while unresolved; at most one sound per reading (the most severe); themes as folders of WAV files | No new dependency and the overlay loop never waits for audio. The default theme is synthesized by a script kept in the repository, so it can be regenerated or replaced. |
| 2026-10-28 | Clean overlay redraw signature includes severity | Caught in simulation: an escalation keeps the same text, so the card stayed yellow. |

| 2026-10-28 | Town center idle alert shows immediately (`persist_s` 0); critical after 10 s | User feedback. The state layer still needs two reads (~2 s) to confirm an empty queue, so one misread cannot fire it. |
| 2026-10-28 | Default sound theme re-synthesized at 44.1 kHz with a bell timbre (inharmonic partials with individual decays, overlapping notes, light reverb, dithering) | The first version (22 kHz, plain sines) sounded low quality. Custom WAV files in a theme folder replace it. |
| 2026-10-28 | Small top-left watermark with version and state (active / paused / waiting) in both overlay modes | User request: confirms the overlay is running without cluttering the screen. |
| 2026-10-28 | Default sounds at about −14/−12 dBFS with energy below ~1.8 kHz (lower notes, fewer partials, low-pass); `sound.volume` (0–1) scales them via cached copies | User heard them as too loud and distorted. The files did not clip digitally; loud, bright sounds were distorting on playback. winsound has no volume control, hence the scaled copies. |
| 2026-10-28 | Population alert: warn at 90% of the cap, critical at the cap | User feedback (was 80% / 90%). |
| 2026-10-28 | Watermark reduced to "aoe4ol <version>" in a very small font; state only in the dot: green all good, yellow some field below 0.75 confidence, red failed field or error, grey no game / menu / waiting | User feedback. The overlay loop now catches unexpected errors and shows the red dot instead of stopping silently. |
| 2026-10-28 | Sounds come from a library (`assets/sounds/library/<name>.wav`) and each severity picks one by name in the config, instead of fixed theme folders | Prepares the planned settings menu (choose a sound per notification from a pool, and later let users add their own). |
| 2026-10-28 | Default sounds are user-provided files: info `blip`, warn `chime`, critical `alarm_low`; `chime_high`, `alarm_bright` and the two synthesized sounds stay in the library as options | The synthesized sounds still sounded odd to the user. Imported files are trimmed, capped at 1.5 s and loudness-normalized (originals peaked at −2.5 to −6 dBFS). Their source/license is "to be confirmed" in SOURCE.md until the links are recorded. |
| 2026-10-28 | Info alerts now play a sound once (no repeat); warn/critical repeat every 5 s | A repeating info sound would chime constantly while resources stay high. |
| 2026-10-28 | Villager queue detection also requires a dark navy border around the best match (max channel ≤ 80, B−R ≥ −5) | Session 20261028-180649: military units (brown), technologies (teal) and production blocked by housing (red, "!") scored 0.57–0.63 on shape alone, at the 0.63 threshold. 22/22 images correct with the border check; three of them are now fixtures. |
| 2026-10-28 | Low-confidence reads (ok but < 0.75) save one `doubt_read_*.png` per (field, value) per match, up to 30 | In the same session 48% of reads had the yellow dot (villagers on food "9" at 0.62, pop "14/45" at 0.73), all correct. The images feed the labeler so the glyph bank grows where it is weak. |
| 2026-10-28 | Sound library sources recorded: Pixabay, Pixabay Content License | User confirmed the origin of the five imported sounds. |
| 2026-10-28 | Income = sum of stockpile increases over the last 60 s of game time, per minute, after a median-of-3 filter; per villager = income ÷ mean villagers on the resource; computed live | The game shows stockpiles only. Spending is ignored, so a drop-off within the same reading as a purchase is partly hidden (test: 260/min for a true 300/min). Cost is a few additions per reading, so it runs live, is logged, and can drive alerts later. |
| 2026-10-28 | Report replays the log through the same state, rules and income code as the overlay; single offline HTML with inline SVG and a little JavaScript | Numbers always match what was shown live; no dependency or network. Palette: categorical slots in the order food, wood, stone, gold, idle (gold on yellow, wood on orange), validated for colorblind separation in light and dark; light-mode contrast is relieved by direct labels and the values table. |
| 2026-10-28 | Audit frames: a JPEG of the bottom-left capture every 10 s of game time in `sessions/<start>/frames/` | Lets the report show what was read at any moment (~15 KB each). |
| 2026-10-28 | Villager and idle regions widened to 30 px (3 digits) with 1 px margin above and below | Session 20261028-180649: two-digit counts touched the 20 px region and lost a digit (23 → 3, 14 → 1) for several readings, which the state layer then accepted. |
